## 修复两个真 bug：Preview 深链空白 + History 删除确认弹窗劫持（2026-09-05 12:30）

### Bug 1：分享深链 `/preview/:id` 全新访客打开 → 一片空白

**根因（React 错误 #310）**：Preview.tsx 把 `isWeChat = useMemo(...)` 写在 `if (!story) return 加载中…` 之后。
首次 render 时 `story=undefined`，走 early return，**没调用那个 useMemo**；加载完成后 `story≠undefined`，**调用了那个 useMemo**。
hook 数量在不同 render 之间变化 → React 抛 "Rendered more hooks than during the previous render" → 整个 Preview 子树没 mount → 整页空白。

**修法**：把 `isWeChat` 移到所有 early return 之前（紧跟 `bg = useMemo(...)`），保证 hook 顺序固定。

### Bug 2：连续删除历史，弹窗"确认"变成"关闭网页"，刷新才好

**根因**：History.tsx 第 71 行用了 `window.confirm('确定删除这个故事吗？')`。
微信 X5 内核对连续 `confirm()` 弹窗会劫持成「关闭网页」，点"确定"按钮失效。
（普通浏览器没问题，但微信里第二次删除开始就会触发劫持。）

**修法**：删掉 `window.confirm`，改用 **inline 二次确认条**（React state 控制 confirmDeleteId，渲染一个红色卡片"确定删除？ 取消 / 删除"）。完全不依赖浏览器原生弹窗，微信 100% 不被劫持。

### 额外：ErrorBoundary 兜底

新建 `components/ErrorBoundary.tsx`，在 App.tsx 把每个 Page 组件单独包一层（带 `scope="Preview"` 等标签）。
任何页面渲染抛错时，显示带具体错误堆栈的兜底 UI，不再神秘空白 —— 这正是我定位 Bug 1 的关键：
没有 ErrorBoundary 之前 `window.onerror` 抓不到 React 渲染错误（hook 错是 React 内部抛的）；加了 ErrorBoundary 后立即看到 `Minified React error #310`。

### 执行
1. 改 Preview.tsx（isWeChat 位置） + History.tsx（删除确认条） + 新增 ErrorBoundary + 包裹 App.tsx 每个 Page
2. `npm run build` → `index-BNWAKFnv.js` + `index-D7qL2XTH.css`
3. `scp` 到 `/var/www/storybook/`
4. 清理服务器旧 JS（验证新 bundle 到位后才删）
5. agent-browser 实测深链 → 完整渲染 rootLen: 16505，所有内容可见

### 教训
**React 错误 #310 / "Rendered more/fewer hooks"**——只要见到这个错就是某个 hook 在 early return 后面没保证调用顺序。
防御性写法：把所有 hooks 集中放在函数顶部、early return 之前。

## History 删除修复（2026-09-05 20:05）

### 问题
历史页内容多时，连续删除出现「顶部 toast 提示已删除，但卡片还在、实际没删掉」；刷新后再删才正常。

### 根因
1. **事件冒泡到卡片按钮**：删除按钮/确认条没有 `stopPropagation`，点击时会冒泡到外层卡片的 `<button onClick={() => nav(...)}>`，触发导航到 preview。快速连续删除时，导航和状态更新竞态，导致列表刷新异常。
2. **缺少删除中状态保护**：连续快速点击确认删除可能产生竞态，重复触发。

### 修复
`frontend/src/pages/History.tsx`：
1. `startDelete` / `cancelDelete` / `confirmDelete` 都加 `e.stopPropagation()` + `e.preventDefault()`。
2. 确认条 div 加 `onClick={(e) => e.stopPropagation()}`。
3. 卡片按钮 onClick 增加保护：若当前卡片正在确认删除，点击卡片其它区域关闭确认条，不再导航。
4. 新增 `deletingId` state，删除中禁用按钮并显示「删除中…」。
5. `confirmDelete` 先检查 `drafts[id]` 是否存在，不存在则 toast 报错并关闭确认条。

### 验证
